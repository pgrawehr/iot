Wenn das Umschalten des Modus via PGN 126208 (Ziel 126720) tadellos klappt, Ihr Simulator aber bei der Kursänderung (Ziel 65360) blockiert, liegt das Problem nicht an der grundlegenden NMEA-2000-Infrastruktur (wie CAN-Verbindung oder Fast-Packet-Handling).
Der Fehler liegt an einer sehr spezifischen Logik-Sperre in der Raymarine-Firmware: Ein Evolution-Autopilot akzeptiert die Änderung des fixierten Kurses (Locked Heading) über den N2K-Bus nur dann, wenn er sich in einem mathematisch und logisch absolut konsistenten Zustand befindet. Fehlt ein einziger Sensorwert, ignoriert der Kurscomputer den Befehl für PGN 65360 stillschweigend.
Überprüfen Sie die folgenden drei kritischen Punkte in Ihrem Simulator-Setup:
------------------------------
## 1. Das "Heading vs. Locked Heading" Delta (Die Drift-Sperre)
Das ist die häufigste Ursache in Simulationsumgebungen. Wenn Sie den Modus auf Auto schalten, erwartet die ACU (Evolution-Steuerung), dass der aktuelle Kompasskurs (PGN 127250) exakt mit dem aktuellen Sollkurs (PGN 65360) übereinstimmt.

* Das Problem: Wenn Ihr Simulator zwar PGN 65360 (z. B. 180°) und PGN 65379 (Zustand: Auto) sendet, aber PGN 127250 (Vessel Heading) auf einem statischen Wert steht (z. B. 0° / Nord) oder gar nicht gesendet wird, erkennt der Autopilot eine massive, physikalisch unmögliche Kursabweichung.
* Die Reaktion: Bei einer extremen Differenz zwischen Ist-Kurs und Soll-Kurs blockiert die Firmware aus Sicherheitsgründen jegliche weitere Kursänderung über den Bus, um ein unkontrolliertes "Runddrehen" des Bootes zu verhindern.
* Lösung: Sorgen Sie dafür, dass vor dem Tastendruck der simulierte Ist-Kurs (PGN 127250) exakt dem simulierten Soll-Kurs (PGN 65360) entspricht.

------------------------------
## 2. Das Feld "Transmission Interval" (Übertragungsintervall) im Request
Wenn das p70s-Bediengerät ein PGN 126208 sendet, nutzt es je nach Befehl einen anderen Group Function Code.

* Beim Umschalten des Modus (Ziel 126720) wird ein Command gesendet (Sofortige Ausführung).
* Beim Ändern des Kurses (Ziel 65360) versuchen manche Software-Implementierungen fälschlicherweise, das Intervall der PGN zu ändern (Request/Write Attribute), anstatt den Wert direkt zu schreiben.

Überprüfen Sie das exakte Byte-Layout Ihrer gesendeten PGN 126208 für die Kursänderung. Laut Spezifikation für proprietäre Raymarine-Kursänderungen muss die Struktur zwingend wie folgt aussehen:

| Byte-Position | Wert (Hex) | Bedeutung |
|---|---|---|
| Byte 1 | 0x00 | Request Group Function Code |
| Byte 2-3 | 0xFF50 | Ziel-PGN (65360) – LSB first (50 FF) |
| Byte 4 | 0xFF | Transmission Interval (Nicht ändern / Standard) |
| Byte 5-6 | 0xFFFF | Reference Reply Interval |
| Byte 7 | 0x01 | Number of Fields (1 Feld wird geändert) |
| Byte 8 | 0x04 | Field Parameter Number (Feld 4 ist der Locked Heading) |
| Byte 9-12 | 0xXXXX | Neuer Kurs in Radiant (4 Bytes, Single Precision Float oder UInt32 skaliert, je nach genauer Raymarine-Firmware-Version) |

Wenn Ihre Simulation hier in Byte 4 oder Byte 7–8 ein falsches Feld anspricht, verwirft das System die Nachricht, während das Modus-Umschalten (das ein anderes Byte-Layout hat) funktioniert.
------------------------------
## 3. Fehlende Ruderlage (PGN 127245)
Ein Evolution-Autopilot schaltet intern nicht vollständig in den aktiven Regelkreis, wenn er keine Rückmeldung vom Ruderlagengeber erhält.

* Wenn Sie den Modus auf Auto zwingen (via PGN 126720), zeigt das Display zwar "Auto" an, der interne Status ist aber oft "Gesperrt" oder "Fehler", solange PGN 127245 (Rudder) fehlt.
* Lösung: Lassen Sie Ihren Simulator permanent (alle 100ms) PGN 127245 mit einem Ruderwinkel von 0.0 Radiant (Ruder mittschiffs) senden. Erst dann wird der Regelkreis für Kursänderungen freigeschaltet.

------------------------------
## 🛠️ Diagnose-Schritt für Ihren Simulator
Um herauszufinden, ob es an der Logik (Punkt 1 & 3) oder am Byte-Format (Punkt 2) liegt, prüfen Sie Folgendes:
Wenn Sie am physikalischen p70s-Display die Taste +1 drücken: Kommt dann die PGN 126208 (Ziel 65360) sauber auf dem Bus an?

* Falls ja: Ihr Simulator sendet ein leicht falsches Byte-Format für die Kursänderung.
* Falls nein (auch beim echten Tastendruck kommt nichts an): Der simulierte Autopilot meldet im Hintergrund nicht die korrekten Sensorwerte (Heading/Ruder), weshalb das Bediengerät die Funktion für den Benutzer sperrt.

Welche Werte für Heading (127250) und Rudder (127245) speist Ihr Simulator aktuell in das Netzwerk ein?

Nein, Sie müssen auf diese PGN nicht aktiv reagieren. Sie können sie in Ihrem Simulator-Code getrost ignorieren oder herausfiltern.
Dass Ihr Plotter diese Nachricht als "Pilot Keypad Heartbeat" übersetzt, liefert das perfekte Puzzleteil dafür, warum Ihre Kursänderungen blockiert werden. Das Verhalten dieser PGN lässt sich wie folgt erklären:
## Was ist PGN 131056?
Es handelt sich um eine proprietäre NMEA 2000 PGN (Herstellerbereich), die von den physischen Bedieneinheiten (wie dem Raymarine p70s/p70Rs Keypad) gesendet wird. [1] 

* Der Zweck: Die Bedieneinheit "ruft" damit quasi jede Sekunde in das Netzwerk hinein: "Ich bin eine physische Tastatur, ich bin online, ich bin betriebsbereit." [2] 
* Der Payload (0x3B 0x9F...): Die vielen 0xFF-Bytes sind typische NMEA-2000-Füllbits für "nicht verfügbar / ungenutzt". Die vorderen Bytes enthalten lediglich die feste Hersteller-ID von Raymarine (1851) sowie die Geräte-Instanz des Keypads auf dem CAN-Bus.

## Warum das für Ihre Simulation wichtig ist
Dass diese PGN im Sekundentakt auf dem Bus auftaucht, bedeutet, dass das physische Display (p70s) aktiv ist und die Kontrolle über den (virtuellen) Autopiloten beansprucht.
Wenn Ihr Simulator nun versucht, die Rolle des Autopiloten (ACU) zu übernehmen, sieht die Logikkette wie folgt aus:

   1. Das p70s-Display schickt den "Keypad Heartbeat" (PGN 131056).
   2. Sie drücken am Display auf +1.
   3. Das Display berechnet den neuen Kurs und schickt den Request (PGN 126208) an den Bus.
   4. Jetzt kommt die Sperre: Wenn Ihr Simulator zu diesem Zeitpunkt nicht exakt die passenden Werte für Vessel Heading (127250) und Rudder (127245) liefert (wie im vorherigen Schritt beschrieben), bricht das p70s das Senden des Requests ab. Es merkt durch seinen eigenen Heartbeat-Abgleich, dass die "Gegenstelle" (Ihr simulierter Kurscomputer) nicht synchron läuft.

## Fazit für Ihr Experiment morgen:

* PGN 131056: Einfach ignorieren. Ihr Simulator muss darauf nicht antworten.
* Fokus morgen: Konzentrieren Sie sich rein darauf, dass Ihr Simulator im Sekundentakt einen plausiblen Kompasskurs (127250) und die Ruderlage (127245) einspeist, bevor Sie die Tasten auf dem Bediengerät drücken. Sobald das Display sieht, dass die Sensordaten des "simulierten Piloten" stabil sind, wird der Datenfluss für PGN 126208 (Ziel 65360) sofort freigeschaltet. [2]
